# Прецедент «Управление документами»

**Рамки.** Приложение «Текстовый редактор».

**Уровень.** Задача, определённая пользователем.

**Основной исполнитель.** Пользователь.

### Заинтересованные лица и их требования

- **Пользователь.** Хочет создавать, открывать, редактировать и сохранять текстовые документы. Хочет видеть изменения документа в процессе редактирования.
- **Операционная система.** Предоставляет интерфейс для работы с файлами.

### Предусловия

Текстовый редактор установлен и доступен для запуска.

### Результаты (Постусловия)

- Документ создан или открыт.
- Изменения документа отражены в контексте редактора.
- Актуальное содержимое документа сохранено в файловой системе.

### Основной успешный сценарий

1. Пользователь запускает программу;
2. Система создаёт контекст текстового редактора;
3. Пользователь выбирает действие «Открыть файл»;
4. Система обрабатывает запрос пользователя, вызывая обновление контекста редактора через модуль взаимодействия с операционной системой;
5. Система создаёт контекст документа и загружает содержимое файла. Полученный контекст документа сохраняется в контексте редактора;
6. Модуль пользовательского интерфейса подхватывает изменение контекста редактора и отображает пользователю его новое состояние - открытый или созданный документ;
7. Пользователь начинает редактировать документ, вводя текст с клавиатуры;
8. Система изменяет содержимое контиекста документа и обновляет контекст редактора. На данном этапе изменения существуют только в оперативной памяти и не сохраняются в файловой системе;
9. Модуль пользовательского интерфейса реагирует на изменение контекста и динамически отображает пользователю изменённое содержимое документа;
10. Пользователь вызывает функцию сохранения документа в файл;
11. Система передаёт актуальное содержимое контекста документа из контекста редактора модулю взаимодействия с файловой системой ОС;
12. Модуль взаимодействия с файловой системой ОС выполняет запись содержимого документа в файловую систему через API операционной системы;
13. Система обновляет контекст редактора, фиксируя сохранённое состояние документа.

### Расширения (или альтернативные потоки)

**3а. Пользователь создаёт новый файл.**

1. Система создаёт пустой контекст документа.
2. Контекст документа добавляется в контекст редактора.
3. Выполнение продолжается с шага 6.

**4а. Не удалось открыть файл.**

1. Модуль взаимодействия с ОС возвращает сообщение об ошибке.
2. Система обновляет контекст редактора, сохраняя информацию об ошибке.
3. Модуль пользовательского интерфейса отображает уведомление пользователю.
4. Выполнение возвращается к шагу 3.

**10а. Пользователь сохраняет новый документ.**

1. Система предлагает пользователю указать имя файла и путь сохранения.
2. Пользователь выбирает расположение файла.
3. Модуль взаимодействия с ОС создаёт новый файл в файловой системе и записывает в него содержимое документа.
4. Выполнение продолжается с шага 13.

**12а. Ошибка сохранения документа.**

1. Модуль взаимодействия с ОС сообщает системе об ошибке записи.
2. Модуль пользовательского интерфейса отображает пользователю сообщение об ошибке.
3. Пользователь может повторить сохранение.

### Специальные требования

- Изменения документа должны отображаться динамически.
- Изменения текста первоначально должны храниться в контексте редактора без немедленной записи в файловую систему.
- Сохранение документа должно выполняться по запросу пользователя.
- Ошибки файловых операций не должны приводить к потере текущего содержимого документа.

### Список технологий и типов данных

- Модуль считывания взаимодействия пользователя с системой.
- Модуль взаимодействия с файловой системой через API операционной системы.
- Ммодуль отображения состояния редактора пользователю.

### Частота использования

Постоянно при работе с текстовым редактором.
