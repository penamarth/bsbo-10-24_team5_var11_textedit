
# Прецедент «Линтинг документа»

**Рамки.** Приложение «Текстовый редактор».

**Уровень.** Задача, определённая пользователем.

**Основной исполнитель.** Пользователь.

### Заинтересованные лица и их требования

- **Пользователь.** Хочет находить и исправлять орфографические ошибки в тексте документа. Хочет получать информацию о найденных ошибках и возможных вариантах их исправления.
- **Средство проверки правописания.** Получает текст документа для анализа и возвращает информацию об обнаруженных ошибках.

### Предусловия

Текстовый редактор запущен. Пользователем открыт или создан текстовый документ.

### Результаты (Постусловия)

- Текст документа проверен на наличие орфографических ошибок.
- Информация об обнаруженных ошибках сохранена в контексте редактора.
- Найденные ошибки отображены пользователю.
- Исправления, выполненные пользователем, отражены в контексте документа.

### Основной успешный сценарий

1. Пользователь вызывает функцию проверки правописания документа;
2. Система получает актуальное содержимое контекста документа из контекста редактора;
3. Система передаёт содержимое документа модулю проверки правописания;
4. Модуль проверки правописания анализирует текст документа на наличие орфографических ошибок;
5. Модуль возвращает информацию об обнаруженных ошибках, включая их расположение в тексте и возможные варианты исправления;
6. Система обновляет контекст редактора, сохраняя полученную диагностическую информацию;
7. Модуль пользовательского интерфейса подхватывает изменение контекста и визуально выделяет найденные ошибки в тексте документа;
8. Пользователь вызывает функцию просмотра найденных ошибок;
9. Модуль пользовательского интерфейса отображает пользователю список найденных ошибок и возможных исправлений;
10. Пользователь выбирает одну из найденных ошибок;
11. Система определяет соответствующий участок в контексте документа;
12. Модуль пользовательского интерфейса отображает пользователю выбранный участок текста и возможные варианты исправления;
13. Пользователь выбирает предложенное исправление;
14. Система заменяет соответствующий фрагмент текста в контексте документа и обновляет контекст редактора;
15. Модуль пользовательского интерфейса реагирует на изменение контекста и динамически отображает исправленный текст;
16. Система инициирует повторную проверку изменённого текста;
17. Модуль проверки правописания возвращает актуальную информацию об ошибках;
18. Система обновляет контекст редактора;
19. Модуль пользовательского интерфейса обновляет отображение найденных ошибок.

### Расширения (или альтернативные потоки)

**5а. Орфографические ошибки не обнаружены.**

1. Модуль проверки правописания возвращает пустой список ошибок.
2. Система обновляет контекст редактора.
3. Модуль пользовательского интерфейса сообщает пользователю об отсутствии обнаруженных ошибок.
4. Пользователь продолжает редактирование документа.

**5б. Не удалось выполнить проверку правописания.**

1. Модуль проверки правописания возвращает сообщение об ошибке.
2. Система обновляет контекст редактора, сохраняя информацию об ошибке.
3. Модуль пользовательского интерфейса уведомляет пользователя о невозможности выполнения проверки.
4. Пользователь может повторить проверку позднее.

**8а. Пользователь выбирает ошибку непосредственно в тексте.**

1. Пользователь выбирает визуально выделенный участок документа.
2. Система определяет связанную с ним орфографическую ошибку.
3. Модуль пользовательского интерфейса отображает описание ошибки и возможные исправления.
4. Выполнение продолжается с шага 13.

**13а. Пользователь исправляет ошибку самостоятельно.**

1. Пользователь редактирует ошибочный участок текста с помощью клавиатуры.
2. Система изменяет содержимое контекста документа и обновляет контекст редактора.
3. Выполнение продолжается с шага 15.

**13б. Пользователь отказывается от исправления.**

1. Пользователь выбирает действие «Пропустить».
2. Система сохраняет содержимое контекста документа без изменений.
3. Модуль пользовательского интерфейса закрывает предложение об исправлении.
4. Пользователь может продолжить работу с другими найденными ошибками.

**\*а. Пользователь изменяет текст после выполнения проверки.**

1. Система обновляет содержимое контекста документа.
2. Ранее полученная диагностическая информация может стать неактуальной.
3. Система инициирует обновление результатов проверки.
4. Модуль пользовательского интерфейса отображает актуальные результаты.

### Специальные требования

- Проверка правописания должна выполняться независимо от формата документа, если из него возможно получить текст для проверки.
- Проверка должна быть ориентирована на орфографию естественного языка, а не на синтаксис Typst.
- Обнаружение ошибок не должно автоматически изменять содержимое документа.
- Каждая найденная ошибка должна быть связана с соответствующим участком текста.
- Изменения документа после исправления ошибок должны первоначально сохраняться только в оперативной памяти.
- Недоступность функции проверки правописания не должна препятствовать редактированию документа.

### Список технологий и типов данных

- Модуль считывания взаимодействия пользователя с системой.
- Самостоятельный модуль проверки правописания.
- Модуль отображения состояния редактора пользователю.
- Данные о найденных ошибках, их расположении и возможных исправлениях.

### Частота использования

По запросу пользователя или регулярно в процессе редактирования документа.

### Открытые вопросы

- Должна ли проверка правописания выполняться автоматически при вводе текста или только по запросу пользователя?
- Какие естественные языки должна поддерживать проверка?
- Как отделять обычный текст от программного кода и других конструкций, не требующих орфографической проверки?
- Нужно ли поддерживать пользовательский словарь?
- Должна ли проверка учитывать контекст предложения или ограничиваться проверкой отдельных слов?
