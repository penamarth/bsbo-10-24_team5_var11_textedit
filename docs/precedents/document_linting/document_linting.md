# Прецедент «Линтинг документа»

**Рамки.** Приложение «Текстовый редактор».

**Уровень.** Задача, определённая пользователем.

**Основной исполнитель.** Пользователь.

### Заинтересованные лица и их требования

- **Пользователь.** Хочет находить и исправлять орфографические ошибки в тексте документа. Текст должен изменяться только по его решению.

### Предусловия

Редактор запущен. Пользователем открыт или создан текстовый документ.

### Результаты (постусловия)

Найденные ошибки выделены в тексте и показаны пользователю. Выбранные пользователем исправления применены к документу; файл на диске не изменён.

### Основной успешный сценарий

1. Пользователь вызывает проверку правописания документа.
2. Система проверяет текст и визуально выделяет найденные ошибки.
3. Пользователь выбирает ошибку; система показывает её описание и варианты исправления.
4. Пользователь выбирает вариант исправления; система заменяет фрагмент текста и обновляет результаты проверки.
5. Пользователь продолжает редактирование документа или вызывает его сохранение.

### Расширения (альтернативные потоки)

**2а. Ошибки не обнаружены.**

1. Система сообщает пользователю об отсутствии ошибок.
2. Сценарий завершается.

**2б. Проверку выполнить не удалось.**

1. Система сообщает об ошибке. Исходный текст остаётся без изменений.
2. Пользователь может повторить проверку позднее.

**3а. Пользователь пропускает ошибку.**

1. Система закрывает предложение об исправлении, текст не изменяется.
2. Пользователь продолжает работу с другими найденными ошибками.

**3б. Пользователь исправляет ошибку вручную.**

1. Пользователь редактирует выделенный участок текста.
2. Выполнение продолжается с шага 4.

***а. Текст изменился после проверки.**

1. Полученные ранее результаты могут устареть; система обновляет их и отображение ошибок.

### Специальные требования

- Проверка относится к орфографии естественного языка, а не к синтаксису Typst и не к оформлению текста.
- Обнаружение ошибок не должно автоматически изменять содержимое документа.
- Каждая найденная ошибка должна быть связана с соответствующим участком текста.
- Недоступность проверки не должна препятствовать редактированию документа.
- Изменения остаются в контексте документа; запись на диск выполняется по отдельной команде из прецедента [«Управление документами»](../document_operations/document_operations.md).

### Список технологий и типов данных

- Текст документа — строка; результат проверки — список ошибок с позициями в тексте и вариантами исправления.
- Интерфейс `Linter` и его реализация `TextLinter`.

### Частота использования

По запросу пользователя или регулярно в процессе редактирования документа.

### Открытые вопросы

- Выполнять проверку автоматически при вводе или только по запросу пользователя?
- Какие естественные языки поддерживать и нужен ли пользовательский словарь?
- Как отделять обычный текст от разметки и кода, не требующих проверки?
- Проверять слова по отдельности или с учётом контекста предложения?
